# Instructions for Codex in VietTTS Human Evaluation Workspace

Before changes, read `CODEX_HANDOFF_TTS.md` and `README.md` for the research requirements and current implementation. Treat `CODEX_HANDOFF_TTS.md` as the project's consolidated requirements and `README.md` as the implementation guide. If there is a conflict between documented requirements and implementation, explicitly report it; do not silently change the experimental label schema.

The current study collects **Single Audio only**: one text-accuracy state, content-error types when `has_error`, and five independent integer 1–5 ratings (`pronunciation`, `intonation`, `pacing`, `audio_quality`, `naturalness`). Do not require or collect `expressiveness` or Pairwise preferences. Keep independent annotations from three separate users per sample, pilot/main split, and evaluator blinding. Don't treat misread audio as invalid or naturalness as an automatic average.

Default light UI, Vietnamese annotator labels, local/LAN deployment only unless production hardening is explicitly requested. Never seed production data with example/fake human labels. Run checks/tests before reporting any change complete. Avoid claims of empirical validation without a real human study. The older Pairwise and six-score descriptions in `CODEX_HANDOFF_TTS.md` are historical; its latest implementation update and the current `README.md` define the active protocol.
